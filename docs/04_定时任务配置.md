# 定时任务配置｜旧 GitLab CI（已停用）

> 已停用：此 CI 方案（每日 09:00 采集 / 周五 17:30 推送）不再使用。
> 现在由 GitHub Actions（`.github/workflows/weekly.yml`）在每周一 15:00（北京时间）
> 运行 `scripts/weekly_refresh.py`，见 README“部署”。
> 下文仅留作历史参考。

`.gitlab-ci.yml` 定义三个 job，全部由 `JOB` 变量分发：

| JOB | 频率 | 做什么 |
|---|---|---|
| `check` | 手动 | 连通性检查：Runner 能否访问采集源与企业微信 API |
| `daily` | 每日 09:00 | 采集 → 抽 Signal → 重算 Idea → 生成 Insight 页面 |
| `weekly` | 周五 17:30 | 生成周报 → 校验深链接 → 推企业微信 |

## 一、配置变量

`Settings → CI/CD → Variables`，两个都勾 **Masked**（日志里打码）：

| Key | Value | 用途 |
|---|---|---|
| `WECOM_WEBHOOK_URL` | 群机器人 Webhook 地址 | 周报推送 |
| `GIT_PUSH_TOKEN` | Project Access Token | 把数据写回仓库 |

Token 在 `Settings → Access Tokens` 建，scope 勾 `write_repository`。

**为什么要写回仓库**：CI 每次从干净仓库启动。采集结果在 `data/radar.db`，
不 commit 回去，下次运行等于从没跑过。

## 二、先跑连通性检查

`Pipelines → Run pipeline`，变量填 `JOB` = `check`，运行。

期望输出：

```
200  https://export.arxiv.org/rss/cs.AI
200  https://openai.com/news/rss.xml
200  https://blog.google/technology/ai/rss/
200  https://www.microsoft.com/en-us/research/feed/
...  https://qyapi.weixin.qq.com/cgi-bin/webhook/send
```

企业微信那条不带 key 请求会返回错误码，只要不是连接失败就说明网络可达。

任何一条 `FAIL ... URLError` 说明 Runner 上不了那个站点，需要配代理或换环境。

## 三、建定时计划

`Settings → CI/CD → Schedules → New schedule`，建两条：

**每日采集**
- Interval pattern：`0 9 * * *`
- Variables：`JOB` = `daily`

**周五推送**
- Interval pattern：`30 17 * * 5`
- Variables：`JOB` = `weekly`

时区选东八区，否则会按 UTC 触发（差 8 小时）。

## 四、确认是否真的推出去了

`weekly_job` 有 5 道闸门，任一不过就只归档不发送，**但退出码仍是 0**——
CI 显示绿色不代表推送成功。要看 artifacts 里的 `outputs/wecom_push_log.jsonl`
最后一行：

| `push` 字段 | 含义 |
|---|---|
| `{"ok": true, "attempt": 1}` | 真的推出去了 |
| `{"skipped": "Insight deep-link verification failed"}` | 有页面 404，见 `failures` 列表 |
| `{"skipped": "WECOM_WEBHOOK_URL not configured"}` | 变量没配或没读到 |
| `{"skipped": "2026-W39 already pushed"}` | 本周推过了，`--force` 可重推 |
| `{"skipped": "WeCom push disabled by project settings"}` | `config/project_settings.json` 里开关是 false |

## 六、每日采集的副作用

`scheduler.py --once` 除采集外还会：

- `verify_stale_sources(limit=10)`：重新验证 30 天未复核的 Raw Source
- `retrieve_needs_verification(limit=1)`：为 1 个高分缺证 Idea 调 arXiv /
  Semantic Scholar 检索证据，**会往 `source_items` 写入新记录**

即每天会自动新增少量 Evidence 源。如果希望采集阶段不自动引入外部检索，
把 `radar/publish/scheduler.py:19` 那行注释掉，改由人工执行
`python -m radar.evidence.evidence_retrieval`。

采集同时会**重算全部 Idea 的分数**（`generate_ideas` + `sync_all_idea_quality`）。
两层人工结论受保护（`radar/core/radar_core.py:826` 与 `:835`）：

- 人工 score override 存在 `ideas.score_overrides_json`，重算时以它覆盖自动分。
- status 为 `approved` 或 `rejected` 的 Idea **不会被自动改状态**。当前 8 个
  rejected 的人工判定因此是安全的。

仍需注意：`candidate` / `watch` 状态的 Idea 会随分数升降档。当前 3 个 Consider
（idea 1 / 2 / 18）都是 `candidate`，采集后可能变动，人工验收结论需复核。
